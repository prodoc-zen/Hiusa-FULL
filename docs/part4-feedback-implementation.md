# PART 4 feedback implementation

The SAO organization register shows two cards per row at tablet width and three on wide screens, with 12 organizations per page. Card actions use the shared three-dot menu. The SAO clearance roster is a table with one row per student, status columns for each required signatory, pagination, and a three-dot action menu. The organization health table keeps a readable minimum width and scrolls inside its card on narrower screens; the top bar hides secondary items before they can crowd out primary controls.

Document tracking lives under **Files > Submitted files**, separate from compliance reviews. It opens on organization folders, supports grid and list layouts and organization search, and presents paginated file rows with document type and semester filters. File actions open protected documents, open a pending registration review, or delete an eligible compliance upload with confirmation. **Files > Storage and limits** holds the disk overview and upload settings. Old `?tab=documents` links redirect to the new document route.

The SAO's **University users** page searches all accounts, including those outside organizations, and filters by role and status. Its detail drawer lists account profiles, clearance signatures, and linked record counts. A separate SAO-only API handles deletion after the matching School ID is supplied and the UI requires it to be typed. The controller removes records whose user foreign keys normally restrict deletion and then deletes the user inside one transaction, auditing the action. This is scoped to the SAO route; organization Admin and profile-removal deletion guards remain in force. Self-deletion and deletion of the final active SAO are refused.

The database's existing cascade rules still apply to other user-owned records. Institutional compliance requirements and clearance periods authored by a deleted SAO are transferred to the acting SAO to preserve shared settings and other students' clearances. A deletion can remove financial, event, order, submission, and personal clearance history, as the confirmation explains. SAO should review the linked record counts before deleting an account.
